# General Skill — Design (per-newsletter, not a shared template)

> **The old "locked Front Desk template as the base for every niche" is RETIRED** (Aug 4 huddle). This file used to define that universal template; it now defines the *principles*, and each newsletter's actual design lives in its own skill (`skills/newsletters/*.md`).

## The core rule
**Every newsletter is its own publication.** A reader who receives two of ours the same day must **never** guess they share a sender. So each newsletter has its **own fonts, colors, logo, images, layout, and topics** — zero shared footprint.

## Universal (apply to all newsletters)
- **White background.** (Drop warm/cream/black-brown pages — white reads more professional.)
- **Wider layout.** Move off the narrow ~600px centered column into a wider, more spacious feel.
- **Its own logo** — distinct per newsletter; no generic shared mark.
- **Its own images** — a distinct visual feel per newsletter; NOT the "canned / vintage / same-source" stock look. Use a different generation tool/model per newsletter if that's what it takes to kill the same-source feel.
- **Keep the formatting craft** (Justin loves it — do NOT change it): the good-morning intro, bolds/italics, text blocks, Short Version/Details/Why It Matters (where the format uses cards), quote/pull-quote blocks, image-as-format.
- Quality over quantity. Keep it simple.

## How design differs by type
Design follows the newsletter's TYPE (see `newsletter-types.md`):
- **Editorial / informational** (Dealmaker, niches) — clean trade-publication look; card or column structure.
- **Independent news** (Referral Channel) — broadcast/newsroom feel (chyron wordmark, strong lead + dispatches).
- **Story / StoryBrand** (Local Affiliate Pro, Main Street) — narrative layout, NOT cards; warmer, human.
- **Donald-Miller storytelling** (Open Source) — narrative + superhero-theme branding.

## Where the actual design lives
Each newsletter's concrete palette, logo, typography, and image direction are specified in its own skill under `skills/newsletters/`. Design fidelity per newsletter is required; do not borrow one newsletter's look for another.
